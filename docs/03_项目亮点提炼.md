## 亮点 1：把「LLM 的不确定输出」关进「确定性工程框架」

**一句话**：独立设计并实现了一套「生成—校验—回炉」闭环，让大模型产出工业级可部署 XML，而不是「能看不能用的文本」。

**底层支撑**：针对大模型「采样随机 + 事实幻觉」两个固有缺陷，逐层引入对应技术形成因果链——用 PEFT/LoRA 微调约束结构风格、用 Pydantic 结构化输出接住格式、用 Chroma RAG 注入私有绑定规则、用三层校验（良构性/schema/业务规则）兜住语义错误、用 Tool Calling 的「决策执行分离」+ human-in-the-loop 保证部署安全。**每一层都在解决上一层的缺陷，不是技术堆砌。**

**面试钩子**：能顺着「幻觉是怎么产生的 → 每一层技术如何对应解决」这条线一口气讲到底，体现的是「理解本质再选技术」，而不是「会调 API」。

## 亮点 2：自研「结构敏感 LoRA」，把业务约束编码进训练目标

**一句话**：在标准 LoRA 基础上做了针对性改进，用 loss 重加权让模型对 XML 结构符号「更敏感」，适配工业结构化生成。

**底层支撑**：工业 XML 里 `<`、`>`、属性名等结构 token「错一个就整段失效」，后果远重于内容词错误；标准 LoRA 对所有 token 一视同仁，于是我在 loss 上按 token 类型加权，等价于把「结构正确」这个业务约束直接编码进训练目标。这是「理解底层 + 做针对性优化」的体现，区别于「拿现成 LoRA 跑一遍」。

**面试钩子**：面试官追问 LoRA 底层（低秩假设、r/alpha、target_modules）都能接住，并落到「我为什么改它」。

## 亮点 3：从 0 到 1 用 LangGraph + MCP + asyncio 搭出可迭代的 Agent 后端

**一句话**：独立搭建了整套 Agent 后端服务，覆盖「状态编排 + 工具服务化 + 异步高并发」三个生产级工程维度。

**底层支撑**：
- **LangGraph 状态机**：把「解析→检索→生成→校验→确认→部署」的控制流显式化，重试循环有界（retry_count + recursion_limit），不会无限循环；
- **MCP 工具封装**：工具做成独立服务，走 JSON-RPC 协议，增删改不影响主流程，实现「配置迭代」；
- **asyncio + FastAPI**：全链路 async，IO 密集的 LLM/检索调用不阻塞事件循环，配合 trace_id 贯穿实现可观测。

**面试钩子**：能回答「为什么 Agent 必须异步」「LangGraph 和 LCEL 什么时候用哪个」「MCP 解决什么问题」这类工程选型追问，体现「能落地、能讲清 trade-off」。

## 简历版（可粘贴到简历项目栏）

> **数控 XML 界面生成与自动部署 AI Agent**（中科院沈阳高精数控 · 实习 · 独立负责后端）
> 基于 Qwen2.5 + PEFT/LoRA 微调 + Chroma RAG + LangGraph + MCP + FastAPI 搭建，实现自然语言 → 工业 XML 界面自动生成与受控部署。核心贡献：① 设计「生成—三层校验—有界回炉」闭环，把大模型不确定输出关进确定性框架；② 自研结构敏感 LoRA，用 loss 重加权提升 XML 结构生成准确率；③ 用 MCP 封装工具服务 + human-in-the-loop 部署确认，保证工业场景安全可控。

## 面试开场 30 秒版

> 我在中科院沈阳高精数控实习，独立负责了一个「数控界面 XML 自动生成 Agent」的后端。这个项目一句话概括：让操作工用一句自然语言就能生成可部署的工业 XML 界面。它的技术价值在于，我面对的核心问题是「大模型输出不确定、但工业场景要求零容错」，所以我做了一套「生成—校验—回炉」的闭环，用 LoRA 微调守结构、RAG 注入规则、三层校验兜底、工具调用加人工确认来保证安全。整个过程从 LangGraph 编排、MCP 工具封装到 asyncio 异步后端都是我从 0 搭的。这套「把不确定关进确定性框架」的思路，是我最想带到贵团队的。
